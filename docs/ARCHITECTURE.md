# 实现架构

## 依赖方向

```text
Forge 游戏入口 / 指令 / 实体呈现 / GameTest
                    ↓
          Simulation 公共用例
                    ↓
  SimulationEngine + EventBus + LoopSystem
                    ↓
       领域规则 → WorldModel 数据契约
                    ↓
             WorldCodec / WorldStore
```

`core` 没有 Minecraft、Forge 或第三方库依赖。`forge` 依赖 `core`，打包时把核心类放入模组 JAR。新增领域规则通过 `LoopSystem` 和 `Definition` 注册，无需更改调度器。领域之间读取共同的数据契约、发布事件，不调用彼此的实现。

每个实例都依次执行感知、评估、决策、执行、反馈、演化。`DomainSystem` 复用批量对象的管线；没有反馈或跨代变化的实例保留空钩子，频率由定义控制。具体公式目前在各领域规则中，世界预算和投放时代通过 Forge 配置调整。

调度使用按到期时刻排列的优先队列，同一时刻按固定注册顺序运行。一次预算耗尽时保留未处理时间，不跳过日期；同一时刻的所有系统完成后才允许形成存档检查点。工作预算限制的是系统批次，不是严格毫秒预算；大人口下仍需要进一步把单批次分片。

随机数由世界种子、系统名、结算时间和实体 ID 混合派生，不依赖 JVM 全局随机序列。存档不用保存内部 PRNG 状态。气候在感知阶段复制区域快照，避免边更新边读取造成空间方向偏差。

## 数据与游戏世界

球面区域由纬经网格和球面板块 Voronoi 分区生成；跨极点翻转经度。气候、生态和文明选址读取该区域模型。**这张模拟球面不是 Minecraft 区块生成器**。实际地形、天空和维度保持原版；城邦在平面世界中的坐标是投影坐标。

文明是只保存统计与成员关系的数据容器。个人根据需求和能力选择活动，重复活动形成角色，再由人数与危机压力聚合出权力中心。当前政治实现仅记录影响权重，不宣称具有完整制度、外交或战争决策。

NPC 持久状态保存在核心中。距离多个玩家最近的区域决定热/温/冷等级，Minecraft 只给热区创建有限数量的村民外壳。外壳死亡会回传核心；外壳卸载不会被视作死亡。村民仍使用原版寻路/AI，这是完整四层 AI 和拼接实体完成之前的交互方式。

建筑复用部件模型，有六个资源消耗阶段。Forge 在已加载区域逐步放置部件，呈现记录防止重启后不断重建玩家修改的房屋。此实现不包括文化风格模板、拆除修复施工和一般建筑蓝图编辑器。

## 时间与持久化

24,000 tick 为一日，24 日为一年，6 日为一季。生成时加速同一个引擎，运行时服务器每 tick 推进一个模拟 tick。睡觉或 `/time set` 暂不改变模拟时钟。快进不移动 Minecraft 的天体或昼夜。

存档格式版本为 1。原子保存包括世界、区域、NPC、资源、建筑、政治权重、科技/魔法进展、玩家身份、符文知识、法术、任务和有限历史。读取校验大小、CRC、ID 唯一性、引用关系。不会反序列化任意 Java 对象，也不会自动覆盖损坏存档。

存档重载一致性通过完整字节比较验证；检查两条相同种子的演化路径以及保存/恢复后继续运行的结果。热区观察者与游戏实体属于运行时对象，不参与持久快照。
